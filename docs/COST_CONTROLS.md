# FridgeOut 成本控制

已接入 iOS 月订阅：US$6.99/月，每个商店账期 20 次；另保留每账号终身 3 次免费试用。权益由后端验证 RevenueCat 的 App Store 状态，客户端不能自报会员。配置和上线步骤见 [iOS 收费](IOS_BILLING.md)。

## 模型调用

每轮最多生成五个候选，一次批量评估所有通过本地规则校验的候选，最多三轮，最终返回最多五个。每轮两个逻辑文本调用，只有明确的 429/5xx 最多重试一次；超时、拒答、格式异常不自动重复。生成输出最多 6,000 tokens，批量评估 2,400，识别 1,800；文本上下文最多 60 KB，图片提示词最多 6 KB。超时仍可能已经产生 provider 费用，取消请求不能保证撤销远端账单。

图片保持 Flare、low、1024×1024、每次一张 JPEG。仍为最多五个最终菜谱各配一张 AI 图片，没有改变为只配一张。图片上传仅由可信后端执行，并校验归属和路径；客户端没有 bucket 的 INSERT/UPDATE 权限，不能直接上传绕过额度。列表使用 360×360 JPEG 缩略图，详情使用原图，不调用付费 Storage 图片变换。

## 额度与预算

| 后端变量 | 默认值 | 含义 |
| --- | --- | --- |
| `FREE_TRIAL_USES` | 3 | 每个账号一共三次免费试用，不限时间、不恢复 |
| `AI_DAILY_BUDGET_USD` | 10 | 全站每 UTC 自然日允许预留的估算金额 |
| `AI_GENERATE_RESERVE_USD` | 0.10 | 一次菜谱操作的保守预留，不含图片 |
| `AI_RECOGNIZE_RESERVE_USD` | 0.02 | 一次识别的预留 |
| `AI_IMAGE_RESERVE_USD` | 0.05 | 一次模型生图尝试的预留 |
| `IMAGE_SPOOL_MAX_BYTES` | 67108864 | 临时恢复目录容量（64 MiB） |
| `IMAGE_SPOOL_DIR` | /tmp/fridgechef-image-spool | 后端临时恢复目录，非用户数据库 |

下载后注册并登录，每个账号总共三次免费试用，无到期时间，不按天或按月恢复。重新安装或换手机不重置同一账号的额度。只有 AI 请求通过额度与预算检查后才记录使用。一次识别包含一次生成（最多五个菜谱）及对应 AI 图片；手动输入库存直接生成也占一次免费使用。识别成功的操作凭证按用户保存在手机，生成通过 `X-Free-Operation` 关联；服务端验证归属和是否已消费。图片凭证从持久菜谱及受保护的生成结果推导，客户端不能自行添加菜谱绕过额度。

菜谱/识别每用户每分钟最多三次预留；同种操作最多一个正在运行。图片每分钟最多六次预留，同用户最多两个正在运行，同一个菜谱一生最多三次付费生图尝试。所有预留使用 PostgreSQL 原子事务和事务级全站锁，多实例也不会同时突破同一个额度或预留预算。

预留失败不会调用模型，返回 429/409。失败的识别和菜谱生成会释放免费/订阅次数；供应商成本预留和生图尝试上限仍保留，因为供应商可能已收费；退款权益由商店状态决定。已有图片读取、轮询和输出恢复不占新生图额度。相同操作 ID 读取已完成结果不重复预留。

$10 是**应用内部预留预算**，不是 OpenAI 账单硬上限，也不包含 Render、Supabase、Expo、商店费用。实际 token 数、价格变动和异常响应可能使账单与估算不同。更换模型或质量时必须同步提高预留金额、更新估算费率；只改模型名称不足以保证成本。OpenAI 控制台用量/账单是最终依据。

`ai_jobs` 保存操作类型、请求指纹、状态、预留金额和成功结果；`ai_usage` 保存 provider 返回的详细用量及估价。它们仅允许 service_role 访问，不能由手机端自报额度。估价费率变量：`AI_TEXT_INPUT_USD_PER_MILLION=0.10`、`AI_TEXT_OUTPUT_USD_PER_MILLION=0.50`、`AI_IMAGE_TEXT_USD_PER_MILLION=5`、`AI_IMAGE_OUTPUT_USD_PER_MILLION=30`。当前模型使用标准短上下文；估价将 cached input 当作未缓存输入，可能偏高。超时/格式错误等没有可用 usage 的情况只能保留预留记录与错误日志，不能还原未知 token 数。费率参考 [OpenAI 官方定价](https://developers.openai.com/api/docs/pricing)。

## 去重与失败恢复

真实模式生成和识别必须传 UUID `Idempotency-Key`。菜谱生成在手机上按用户保存未完成请求 ID；网络失败后再次点击、或重启 App 后恢复同一输入，会重用 ID。成功后移除本地 ID，明确失败后允许下一次主动点击开启新操作。数据库中的 running 记录最长十二分钟；过期后判为失败，不自动再次调用模型。库存或偏好改变会创建新的操作。

同一个 UUID 不能跨输入/类型复用；不同用户即便用同一个 UUID 也互不共享结果。合格菜谱批量写入并渐进显示，失败可能留下部分菜谱，应先查看当前生成结果再重试。

生图完成后先暂存输出，上传最多重试三次同一份字节。失败后手动重试优先恢复暂存输出或已上传原图，再补缩略图/数据库状态；不重新调用模型。临时文件最长保留二十四小时，超出 64 MiB 时淘汰最旧文件，文件权限为 0600。Render 重部署/实例更换可能丢失临时文件；模型返回后尚未保存输出的崩溃也无法完全恢复，这些情况仍可能需要一次新的付费尝试，受图片次数和预算限制。

前端轮询从五秒逐渐延长到三十秒，三分钟停止；显式点击可以再次检查。已 ready 的图片仅获取签名 URL，不重复生图；URL 有效一小时，App 查询缓存五十分钟。旧图片没有缩略图时回退原图。

## 数据清理

用户点击 Save 后存入 `favorite_recipes`，收藏不限数量、不因年龄删除。生成结果先放在 `recipe_drafts`，最多五份，下一轮成功生成时清理上一批未收藏结果，闲置超过 24 小时后台清理。迁移 010 会删除旧 History，清除缓存副本并排队删除图片，不自动转换为收藏。手动删除收藏永久删除记录及 `ai_jobs.result` 中的副本和空 recipe_sessions。删除菜谱/账户时触发器把图片路径放入 `image_cleanup_queue`，包含缩略图。生成和手动删除后立即尝试清理该用户图片；后台仅清理没有菜谱引用的路径，失败持久保存重试时间，不会因为一次 Storage 故障永久漏掉。

后台还扫描 `recipe-images` bucket 中超过二十四小时、没有菜谱引用的孤立图片；年轻文件视为可能仍在上传。清理通过 Storage API 删除文件，不直接删除 Storage 元数据。仅 service_role 能执行全用户清理或修改队列，用户路径校验阻止跨账号图片删除。

API 启动及运行期间每六小时分批处理，默认一批一百条，不增加付费 worker。免费 Render 休眠会延迟清理；积压较大时需增加运行频率/批量。内部操作和用量记录通常保留九十天；未使用的识别生成凭证，以及仍保留菜谱的生成授权和生图尝试记录会保留更久，以保证试用没有期限并维持生图尝试上限。终身免费次数账本不会随定期清理重置。删除账户会清除缓存私人结果和详细用量，但不会抹去当天预算预留记录。

## 上线与验收

先在 Render 配置 backend-only `SUPABASE_SERVICE_ROLE_KEY`（同项目 legacy service_role JWT），然后由 Actions 应用 003–013 迁移，再部署后端并更新手机端。密钥缺失或账本不可用时拒绝新付费调用；demo 模式不依赖费用账本。MCP 子进程不继承管理员密钥。没有新增 `.env.example`，本地仍只使用 `backend/.env`。

自动测试涵盖模型超时不重复、批量评分映射、图片并发去重和输出恢复、拒绝额度后不调用 provider、RLS/账本权限、真实并发预算、显式收藏、无限收藏数量、旧 History 删除和草稿清理、孤立图片及持久清理重试。测试使用模拟模型和本机 PostgreSQL，不代表已验证真实模型质量、云端凭据或线上账单。
